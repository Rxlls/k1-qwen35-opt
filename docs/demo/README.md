# 真机演示视频

两段录像，都在 K1 本机录制（labwc/Wayland + grim 连拍 + x264），未使用外部录屏设备。

| 文件 | 时长 | 内容 | 用途 |
|---|---|---|---|
| `k1-2b-ab.mp4` | 55.6 s | **对照**：同一段 534 token 提示词，官方 Q4_0 与自产 Q4_0 各跑一次 | 证明 +80.6% 的来源（答辩主用） |
| `k1-2b-demo.mp4` | 37.3 s | 单模型：2B 自产 Q4_0 生成中文 | 展示设备可用、出字正常 |

## k1-2b-ab.mp4 的画面内容

```
0–3 s     片头（对照实验说明）
3–6.6 s   终端：A/B 两个模型的定义、提示词说明
6.6–28 s  A · 官方 Q4_0 预填充 534 token（4× 快进，右上角有角标）
28–31 s   定格：Prompt 9.8 t/s ｜ Generation 2.6 t/s
31–52 s   B · 自产 Q4_0 同一提示词（4× 快进）
52–55 s   定格：Prompt 17.7 t/s ｜ Generation 2.7 t/s
55 s–     片尾：四列对照表 + 与归档值的差异说明
```

**两点必须说明**（片尾卡上也印了）：

1. **绝对值低于归档值**：画面 9.8 → 17.7（+80.6%），归档 10.84 → 20.36（+87.8%）。
   原因是录制时每 0.14 s 抓一帧，`grim` 读帧约占 1 核（4 核里的 1 核），两个模型同时被拖慢。
   比例仍接近（1.81× vs 1.88×），因为拖慢对两者是同向的。
2. **decode 基本不变**（2.6 / 2.7），收益集中在 prefill —— 这正是机制分析要说明的：
   18 个 `ssm_out` 是 Q5_K，prefill 阶段要跑 18×512 次标量路径，decode 每 token 只跑 18 次、
   被带宽掩盖。

## 复现

```bash
# 在 K1 上（会自动开终端、抓帧、编码，约 3 分钟）
bash tools/record_ab.sh /tmp/k1_ab.mp4

# 在本机合成（片头 + 4× 快进 + 定格 + 片尾）
python tools/make_cards_ab.py
python tools/compose_ab.py --video /tmp/k1_ab.mp4 --phases /tmp/cie_phases.saved.log
```

`tools/compose_ab.py` 读取 `demo_ab.sh` 写入的阶段时间戳（`/tmp/cie_phases.log`），
按真实时间剪辑，不做固定帧率假设——所以快进是准确的 4×，不是估算。

## 已知限制

- 帧率约 7 fps（受 `grim` 单帧 120 ms 限制），4× 快进后正好接近 30 fps，观感尚可；
  正常速度段会略显不连贯。
- 无音频、无鼠标指针（脚本预置，不在 GUI 里交互）。
- `wf-recorder` 未安装（sudo 需密码），所以拿不到 30 fps 的原生录屏。
