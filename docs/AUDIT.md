## 3. 本轮发现的两个流程陷阱（比数据本身更值得记）

### C1 · 孤儿进程会让所有测量静默失真

`ssh` 会话被超时 SIGTERM 后，**子进程 llama-bench / llama-cli 不会随之退出**。今晚因此出现：

- 两个残留进程（一个 `llama-cli` 跑了 18 分钟、一个 `llama-bench` 跑了 3 分钟）把 load 推到 8.5；
- 期间测得的 4 线程 pp128/tg64 = 5.94 / 1.08（真值 11.08 / 2.89）、v0.2.3 = 3.74 / 0.79（真值 8.22 / 3.22）——
  **我差点据此写下"文档数据不可复现"的错误结论**。

**规程**：每次测量前 `pkill -9 -f "llama[-]cli"; pkill -9 -f "llama[-]bench"`，确认 `load < 1` 再开跑；长跑一律带 `timeout` 并在结束前 kill 残留。

### C2 · 本机两个会"挂住"的配置

| 配置 | 现象 | 建议 |
|---|---|---|
| `llama-cli -c 32768` | 101% CPU、18 分钟无输出（`--no-mmap`） | 32K 内存重测需换设备状态或改用 `-c 16384` 外推；已记 `results/ctx32k_2b_hang.txt` |
| `llama-bench -t 8` 的 tg 组 | 240 s 未完成 | 不要用 `-t 8` 跑长测 |

  但 `ps` 采样到 RSS **1,823,992 KB ≈ 1.74 GiB**，与文档量级一致（差 0.09%）。

## 6. 核对结论

1. **核心论证链完整且可复现**：量化类型 → IME 白名单 → prefill 翻倍（+87.8% / +113.2%），有归档 bench、有张量级证据、有独立复跑。
2. **两条"方法论贡献"里，温度那条已被我们自己的实验推翻并撤回**，替换为有据的跨架构复核判据——文档不再包含无法复现的强主张。
3. **B2/B3 从"无归档"升级为"已复现"**，且 B2 的结论比记录更强（8 线程 decode 比 0.86 t/s 更慢）。
4. **B1 仍未闭环**（32K 内存只有观测值 + 单位已修正），是唯一还缺原始归档的数字。
5. **流程陷阱 C1 是今晚最大的收获**：在此之前，"复现不出"与"数据错误"无法区分；现在有了明确的测量前置条件。
